# Certificates

Scenarios either bring their own certificate files (fixed sets in `certs/`) or get a fresh
PKI per run ([certificate refill](functional/certificate-refill.md)). The fixed sets are
**test material**: their private keys are committed and must never be used outside the
simulation. `certs/README.md` lists the files and their validity.

## Fixed sets

The repository's `certs/` is mounted read-only into every station at `/vnap-certs`. A
scenario's `certs_dir` mounts another directory instead (see
[scenario format](reference/scenario-format.md)).

### `certs/c-its-pki/` (v3, `certs-v3`)

Generated by C-ITS-PKI's `gen-vnap-certs.sh`:
- the authorities: `root_ca`, `aa`, `ea` and `tlm`;
- a regular AT (`at.cert` / `at.der`), used by RSUs;
- 24 butterfly ATs (`bke_at_<j>.cert` / `bke_at_<j>_sign.der`), used by the fixed pseudonym
  pools.

C-ITS-PKI's `docs/compliance.md` documents their conformance.

**Regenerate** (from vnap-secure, with the submodule):

```bash
cd ${VNAP_HOME}/external/C-ITS-PKI
./gen-vnap-certs.sh        # v3; with any argument: v2
```

- **Where it writes:** `TARGET_DIR`, which defaults to this repository's `certs/c-its-pki`
  (found from the submodule or from a checkout next to vnap-secure).
- **What it replaces:** the script deletes the old `*.cert` and `*.der` there. Scenarios that
  use the set keep working as long as the file names stay the same.

### `certs/certify/` (v2, `certs-v2`)

- **Origin:** generated with Vanetza's `certify` tool (TS 103 097 V1.2.1 format).
- **Contents:** a root and AA (`root_ca_vnap`, `aa_vnap`), and per-station ATs
  `ticket_vnap_{rsu,obu}_20260924`, valid until 2026-11-23.
- **Used by:** the `certify-fresh` scenario.

**Regenerate:**

```bash
scripts/certs/certify-shell.sh          # shell in vnap:latest with certs/ at /vnap-certs
# inside: run the steps of scripts/certs/gen-certify.sh (it empties /vnap-certs/certify first),
# or issue only new ATs from the existing root and AA:
certify generate-ticket --output /vnap-certs/certify/ticket_vnap_obu_<date>.cert \
    --subject-key <key> --sign-key /vnap-certs/certify/aa_vnap.key --sign-cert /vnap-certs/certify/aa_vnap.cert \
    --days 60 --cam-permissions '1111111111111100' --denm-permissions '000000000000000000000000'
```

Then update the file names in `sim/scenarios/certify-fresh.toml`.

## Key formats

socktap loads private keys as PKCS#8 DER (v3 also accepts PEM). Keys from `certify` and
C-ITS-PKI already have that format. To convert a PEM key:

```bash
scripts/certs/convert-sign-key.sh <key.pem>     # writes <key.pem>.der and prints it
```

## Trust configuration

The [container environment](reference/container-environment.md) sets the certificates:
`AT_CERT` / `AT_KEY` (or a pseudonym pool), `AA_CERT` and `ROOT_CERT`. In scenarios, the
station and default keys `at_cert`, `at_key`, `aa_cert`, `root_cert` and `pseudonyms` set
them. The negative controls point `root_cert` at the wrong certificate on purpose
(`c-its-pki-badroot` trusts `tlm.cert`). How the stations check chains is described in
[security and chain verification](functional/security-and-chain-verification.md).
